Antes dos comandos: o que estamos fazendo?

O código da oficina será compilado e empacotado em uma imagem Docker. Depois enviaremos essa imagem para um repositório privado na AWS. Publicar a imagem não inicia a aplicação e não cria o PostgreSQL.

Código + Dockerfile → Imagem local → Tag com destino → ECR na AWS
TermoSignificado no seu projeto
ImagemPacote com o executável da API e o necessário para executá-lo. É construído pelo Dockerfile.
ContainerUma execução de uma imagem. A imagem pode existir sem nenhum container rodando.
RegistryServidor que armazena repositórios de imagens. Exemplo: 123456789012.dkr.ecr.us-east-1.amazonaws.com.
RepositórioGrupo de imagens dentro do registry. Usaremos oficina-api.
TagNome atribuído a uma versão da imagem, como v1 ou v2. É um rótulo; não é uma versão criada automaticamente pelo Docker.
DigestIdentificador do conteúdo de um manifesto, no formato sha256:.... Permite referenciar conteúdo específico; uma tag pode mudar de destino se o repositório permitir.
Perfil AWSNome local que seleciona credenciais e configurações. academy foi o nome usado no seu computador; fiapaws é a convenção da aula.

Anatomia do endereço da imagem

123456789012.dkr.ecr.us-east-1.amazonaws.com/oficina-api:v1
└──────────────── registry ──────────────┘ └repositório┘ └tag

O número inicial é o ID da conta AWS. us-east-1 é a região. A barra separa o registry do repositório; os dois-pontos separam o repositório da tag.

O ID 123456789012 é fictício e serve apenas como exemplo. Substitua pelo ID da sua conta antes de usar. ID de conta não é uma senha; as chaves e o token são credenciais.

Prepare o acesso ao laboratório

No AWS Academy, inicie o Learner Lab e abra AWS Details → AWS CLI → Show. Quando houver novas credenciais ou as antigas expirarem, atualize os três valores abaixo.

notepad "%USERPROFILE%\.aws\credentials"

O arquivo deve se chamar credentials, sem .txt. Ele contém este formato:

[academy]
aws_access_key_id=COLE_A_ACCESS_KEY
aws_secret_access_key=COLE_A_SECRET_KEY
aws_session_token=COLE_O_SESSION_TOKEN

A CLI procura automaticamente a pasta .aws do usuário atual. %USERPROFILE% é uma variável do CMD que normalmente representa C:\Users\SEU_USUARIO. A pasta do projeto não influencia essa busca.

aws configure set region us-east-1 --profile academy
aws configure set output json --profile academy

aws configure set grava configurações da CLI. Não confunda com o comando set do CMD, que cria variáveis no terminal. Região e formato ficam salvos em %USERPROFILE%\.aws\config, normalmente sob [profile academy]. No arquivo credentials, o cabeçalho é somente [academy].

Windows e WSL têm pastas pessoais diferentes. Este guia usa o CMD do Windows. Os comandos set, %VARIAVEL% e cd /d abaixo não são a sintaxe do PowerShell ou do Bash. Nunca coloque credenciais no HTML, Dockerfile, imagem ou Git.

Publicação, passo a passo

Execute uma etapa por vez no mesmo CMD. Se houver erro, resolva essa etapa antes de continuar. Mantenha o Docker Desktop aberto, com suporte a containers Linux.

01Conferir identidade e Docker

aws sts get-caller-identity --profile academy --no-cli-pager
docker info

Por quê? O primeiro comando confirma a identidade da sessão AWS e retorna UserId, Account e Arn. Ele não cria recursos. Confira o campo Account, pois será usado no endereço do ECR.

--profile academy seleciona o perfil salvo. --no-cli-pager mostra o resultado diretamente no terminal, sem um visualizador paginado. docker info verifica se o cliente consegue conversar com o mecanismo do Docker Desktop.

Esperado: identidade AWS válida e informações do Docker sem erro de conexão.

02Entrar na pasta do projeto

cd /d "C:\projetos\pos-fiap-oficina-mecanica"

Por quê? Os comandos seguintes usarão o Dockerfile e o código desta pasta. No CMD, cd muda o diretório e /d também permite mudar de unidade, por exemplo de D: para C:. As aspas protegem caminhos que contenham espaços.

03Construir a imagem da API

docker build -t oficina-api:v1 .
docker images oficina-api

Por quê? docker build executa as instruções do Dockerfile. -t atribui o nome oficina-api e a tag v1 ao resultado. O ponto final . define a pasta atual como contexto de construção: os arquivos disponíveis para instruções como COPY, respeitando o .dockerignore.

No Dockerfile analisado, uma etapa com Go compila o código e uma segunda etapa com Alpine recebe o executável. A imagem final executa com usuário sem privilégios de root. Não é necessário iniciar PostgreSQL para esse build. As tabelas e os dados do banco não são incluídos nessa imagem.

Esperado: construção concluída e uma linha com oficina-api / v1 na listagem. Construir a imagem não cria um container em execução.

04Criar o repositório privado

aws ecr create-repository --repository-name oficina-api --region us-east-1 --profile academy --no-cli-pager

Por quê? Precisamos de um destino no ECR para guardar as versões da API. --repository-name define o nome desse destino; --region define onde ele será criado, explicitamente, mesmo se houver outra região configurada no perfil.

Esperado: JSON contendo repositoryUri. Se retornar RepositoryAlreadyExistsException, o repositório já existe nessa conta/região; confira seu endereço e continue. Não precisa recriá-lo a cada versão.

Esta etapa cria um recurso na AWS. As imagens armazenadas podem consumir o orçamento do laboratório. Permissão para listar repositórios não garante permissão para criar ou publicar.

05Guardar o endereço com set

set ECR_REGISTRY=123456789012.dkr.ecr.us-east-1.amazonaws.com
echo %ECR_REGISTRY%

Por quê? set é um comando do CMD que define uma variável de ambiente na sessão atual. Aqui guardamos um endereço longo para reutilizá-lo sem redigitar.

docker tag oficina-api:v1 %ECR_REGISTRY%/oficina-api:v1

Antes de executar esse comando, o CMD substitui %ECR_REGISTRY% pelo valor armazenado. O Docker recebe o endereço completo.

  • O nome ECR_REGISTRY foi escolhido por nós. Não é uma variável obrigatória da AWS.
  • O set não cria repositório, não autentica e não envia nada.
  • A variável vale no CMD atual e nos processos iniciados por ele; não fica configurada permanentemente. Em um novo CMD, defina-a novamente.
  • Não coloque espaços em volta do =. Confira o resultado com echo.
  • Você pode escrever o endereço inteiro em cada comando; o resultado é o mesmo.

Antes de copiar: substitua o ID da conta caso o passo 01 retorne outro número. O endereço deve corresponder ao registry de repositoryUri retornado no passo 04, sem /oficina-api e sem https://.

06Autenticar o Docker no ECR

aws ecr get-login-password --region us-east-1 --profile academy | docker login --username AWS --password-stdin %ECR_REGISTRY%

Por quê? A CLI usa suas credenciais do Academy para obter uma senha de autenticação do ECR. O Docker usa essa senha para acessar o registry privado. Estar autenticado na CLI não autentica automaticamente o Docker.

TrechoO que significa
get-login-passwordObtém a senha de autenticação do ECR.
|Pipe: encaminha a saída do comando à esquerda para a entrada do comando à direita.
--username AWSO usuário é literalmente AWS, não o seu e-mail.
--password-stdinLê a senha da entrada padrão, em vez de incluí-la como argumento na linha de comando.

Esperado: Login Succeeded. O token de autenticação do ECR é válido por 12 horas; a sessão temporária e as permissões do laboratório também precisam estar válidas para as operações. Se necessário, renove as credenciais do Academy e repita o login.

07Adicionar a tag com o destino completo

docker tag oficina-api:v1 %ECR_REGISTRY%/oficina-api:v1
docker images

Por quê? O nome local oficina-api:v1 não contém o destino na AWS. docker tag ORIGEM DESTINO cria outra referência local para a mesma imagem, agora com registry, repositório e tag.

Não recompila, não faz upload e não duplica o conteúdo da imagem. As duas referências normalmente aparecem com o mesmo IMAGE ID na listagem local.

v1 é uma convenção nossa. Poderia ser 1.0.0 ou sha-abc123. A tag latest também é apenas um nome: não significa que o Docker escolheu a imagem mais recente. Ao omitir a tag nestas referências, o Docker usa latest.

08Enviar a imagem para a AWS

docker push %ECR_REGISTRY%/oficina-api:v1

Por quê? Este é o comando que publica as camadas e o manifesto da imagem no ECR. Camadas já disponíveis podem ser reaproveitadas.

Esperado: progresso do envio e, no final, um digest sha256:.... A imagem continua no computador após o push. Nenhuma API é iniciada na AWS por esse comando.

09Confirmar a publicação

aws ecr describe-images --repository-name oficina-api --image-ids imageTag=v1 --region us-east-1 --profile academy --no-cli-pager

Por quê? A consulta verifica o conteúdo remoto, não apenas a cópia local. --image-ids imageTag=v1 seleciona a tag que acabamos de publicar.

Esperado: detalhes com imageTags incluindo v1 e um imageDigest. No console, selecione a região Norte da Virgínia (us-east-1) e abra ECR → Private repositories → oficina-api.

10Encontrar a imagem no Docker Desktop

Na área Images de imagens locais, procure oficina-api:v1 e a referência completa do ECR. Ambas são locais. Para ver o que está na AWS, consulte o ECR.

A área Containers mostra execuções, não o catálogo de imagens. Para executar a oficina, será necessário fornecer as variáveis de ambiente e um PostgreSQL preparado. Usar Run sem essas dependências não basta.

Alterei o código. Como publico a próxima versão?

Use uma tag nova para distinguir os artefatos. Reiniciar um container não recompila o código Go que já foi empacotado.

docker build -t oficina-api:v2 .
docker tag oficina-api:v2 %ECR_REGISTRY%/oficina-api:v2
docker push %ECR_REGISTRY%/oficina-api:v2

Antes disso, confirme credenciais válidas, defina ECR_REGISTRY se abriu outro CMD e repita o login se necessário. O repositório oficina-api pode ser reutilizado.

E o Kubernetes? O Deployment analisado usa oficina-api:local. Para consumir a versão publicada, sua imagem deverá apontar para o endereço completo com :v1 ou :v2. O cluster também precisa de autorização para baixar do ECR privado e de acesso ao PostgreSQL. O login do Docker no computador não configura automaticamente a autenticação dos nós Kubernetes. Publicar uma tag nova não atualiza os Pods por conta própria.

Diagnóstico rápido

The config profile (academy) could not be found

Confira %USERPROFILE%\.aws\credentials, sem extensão .txt, e o cabeçalho [academy]. Um arquivo chamado academy.txt não é carregado automaticamente. O nome do perfil é a seção dentro do arquivo, não o nome do arquivo.

ExpiredToken ou InvalidClientTokenId

Atualize access key, secret key e session token juntos, com os valores da mesma sessão do laboratório. Confirme o perfil e repita aws sts get-caller-identity --profile academy.

AccessDenied

Leia qual operação foi negada. Conseguir autenticar ou listar repositórios não garante permissão para criar repositórios, obter autorização do ECR ou enviar imagens. Consulte as restrições e permissões do laboratório.

Docker não conecta ao engine

Abra o Docker Desktop, espere a inicialização e teste docker info. Confira o uso de containers Linux e o contexto Docker selecionado.

no basic auth credentials ou token expirado no push

Repita o login do passo 06 para o mesmo registry e região do destino. Se a sessão Academy expirou, atualize suas credenciais primeiro.

Imagem ou tag não encontrada

Use docker images para verificar nomes locais e tags. Confirme que o build terminou e que o passo docker tag foi executado com o endereço correto. Na AWS, confirme conta, região, repositório e tag consultados.

A variável aparece como %ECR_REGISTRY% ou está vazia

Este guia é para CMD. Execute o set ECR_REGISTRY=... na mesma janela dos comandos seguintes. PowerShell usa outra sintaxe: $env:ECR_REGISTRY = "endereco" e $env:ECR_REGISTRY.
